# Visual Style Selector

Choose a visual language that serves the product rather than defaulting to familiar templates.

## Evaluate context

Consider:
- Audience expectations, domain risk, and trust requirements.
- Brand positioning and personality.
- Content density and information complexity.
- Primary user journeys and conversion goals.
- Available photography, illustration, product imagery, and brand assets.
- Implementation budget, performance, and accessibility.

## Selection method

1. Review the art direction and project constraints.
2. Select one dominant visual language (for example editorial, minimal product-led, expressive typographic, refined enterprise, immersive campaign, or warm human-centered).
3. Choose supporting traits only when they reinforce the dominant language.
4. Define a reference set by purpose: typography, composition, interaction, imagery, and color. Do not use one site as a blueprint.
5. Translate references into reusable rules and original compositions.
6. Check that the style remains legible and coherent on mobile, with real content and without motion.

## Reject style drift

Do not combine unrelated visual tropes merely to make a page “look premium.” Avoid default gradients, glassmorphism, oversized rounded cards, floating blobs, arbitrary glow, decorative grids, and stock illustrations unless they are justified by the concept. Equally, do not reject these techniques categorically: use them when they have a clear role.

## Decision record

Document:
- Dominant style and why it fits.
- Supporting visual traits.
- Reference sources and what is being learned from each.
- Rules that should remain consistent across pages.
- Techniques explicitly excluded.
- Risks to usability, accessibility, performance, or responsive behavior.
