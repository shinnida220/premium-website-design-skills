# Mobile Web Design

Treat mobile as a first-class context with its own constraints and opportunities—not a desktop layout reduced in size.

## Understand context
Identify mobile tasks, likely network/device constraints, input methods, content priorities, and whether users are on the move or in a focused session.

## Design workflow
1. Rank mobile tasks and content; keep essential information and actions easy to reach.
2. Establish a robust single-column foundation, then add complexity as space allows.
3. Design navigation for touch, keyboard, screen readers, and predictable back behavior.
4. Use appropriate target sizes and spacing; avoid dense clusters of controls.
5. Keep forms short, use suitable input types, and preserve entered data.
6. Optimize imagery, fonts, scripts, and loading behavior for constrained networks.
7. Avoid sticky UI that consumes too much viewport or obscures content.
8. Check safe areas, browser chrome, orientation changes, zoom, and dynamic text.
9. Test on real devices when available; emulation is useful but not a complete substitute.

## Rules
- Do not hide important content merely to simplify the mobile page.
- Do not rely on hover, tiny icons, or precise gestures.
- Do not disable pinch zoom.
- Avoid autoplay media and heavy animation that harms battery or data usage.
- Make touch interactions tolerant of imperfect input.

## Deliverable
Provide mobile task priorities, navigation pattern, layout behavior, touch/keyboard rules, performance considerations, and device/browser test evidence.
