# Anti-patterns and corrective actions

These are warning signs, not absolute bans. A technique is acceptable when it serves the product, content, and users.

| Warning sign | Why it underperforms | Better response |
|---|---|---|
| Generic hero with vague headline | Does not communicate audience or value | State a concrete outcome and supporting proof |
| Every section is a row of cards | Flattens hierarchy and creates visual repetition | Vary composition according to content purpose |
| Random gradients and glow | Visual decoration lacks meaning | Tie color and effects to a defined brand concept |
| Excessive rounded containers | Makes the interface feel templated | Use shape as a deliberate system, not a default |
| Placeholder logos/testimonials | Misleads users and damages trust | Use approved evidence or omit the section |
| Stock image unrelated to content | Adds noise rather than meaning | Use relevant product imagery, diagrams, or purposeful photography |
| Tiny muted text | Reduces readability and contrast | Increase size/contrast and clarify hierarchy |
| Desktop layout simply shrunk | Creates cramped mobile experience | Recompose order, layout, and actions |
| Hover-only interactions | Excludes touch and keyboard users | Provide focus, click/tap, and semantic controls |
| Motion without purpose | Distracts, slows, or causes discomfort | Explain state or reinforce narrative; honor reduced motion |
| Fixed heights around variable content | Causes clipping and overflow | Prefer content-driven sizing and robust wrapping |
| Too many competing CTAs | Makes next action ambiguous | Establish primary and secondary action hierarchy |
| Fake product UI or metrics | Creates false expectations | Use real product evidence or label conceptual mockups |
| Arbitrary breakpoints | Layout fails near transitions | Derive breakpoints from content pressure |
| No empty/error/loading states | Product UI feels unfinished | Design realistic state coverage |
